# CÓDIGO DA APLICAÇÃO

## Objetivo desta pasta

Esta pasta serve para guardar o código-fonte e os ficheiros necessários ao desenvolvimento da aplicação de geração automática de palavras cruzadas.

O objetivo é manter o código organizado, facilitando o desenvolvimento, a correção de erros e o trabalho em equipa.

## O que deve ser colocado aqui?

### 1. Código-fonte

Ficheiros que contêm as instruções responsáveis pelo funcionamento da aplicação.

**Responsável principal:** Programador.

### 2. Interfaces gráficas

Ficheiros responsáveis pelos ecrãs, menus, formulários e restantes elementos visuais com que o utilizador interage.

**Responsável principal:** Programador.

### 3. Algoritmos de geração de palavras cruzadas

Código responsável por gerar as palavras cruzadas, organizar as palavras e preencher a grelha de acordo com as regras definidas.

**Responsável principal:** Programador.

### 4. Base de dados

Ficheiros e scripts necessários para criar, configurar e utilizar a base de dados do projeto.

**Responsável principal:** Programador, com a colaboração do Analista / Arquiteto de Sistemas na definição dos requisitos e da estrutura necessária.

### 5. Comunicação cliente/servidor

Código responsável pela comunicação entre o cliente e o servidor, de acordo com a arquitetura definida para a aplicação.

**Responsável principal:** Programador, com base na arquitetura acordada com o Analista / Arquiteto de Sistemas.

### 6. Integração das funcionalidades

Ligação entre os diferentes componentes para garantir que a autenticação, a geração de palavras cruzadas, a seleção da dificuldade e a gravação do progresso funcionam em conjunto.

**Responsável principal:** Programador.

## Regras de organização

- Os ficheiros devem ter nomes claros e fáceis de compreender.
- O código deve estar organizado por funcionalidades.
- As alterações devem ser guardadas no GitHub regularmente.
- Antes de modificar código desenvolvido por outro membro, deve verificar-se o seu funcionamento.
- Não devem ser colocadas palavras-passe, chaves privadas ou outros dados confidenciais no repositório.
- As tecnologias e a estrutura definitiva devem ser acordadas pelo grupo antes do desenvolvimento das funcionalidades principais.

## Resultado esperado

No final, esta pasta deve conter o código organizado da aplicação, permitindo desenvolver, testar, corrigir e manter o software de forma colaborativa.
