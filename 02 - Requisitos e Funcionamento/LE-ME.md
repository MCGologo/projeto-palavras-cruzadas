# REQUISITOS E FUNCIONAMENTO

## Objetivo desta pasta

Esta pasta serve para documentar o que a aplicação deve fazer, como deve funcionar, como será organizada e quais são os requisitos que tem de cumprir.

O projeto consiste no desenvolvimento de uma aplicação capaz de gerar automaticamente palavras cruzadas.

## O que deve ser colocado aqui?

### 1. Especificação de requisitos

Documento que descreve as funcionalidades que a aplicação deve disponibilizar e as condições que tem de cumprir.

Requisitos funcionais definidos no enunciado:

- **RF1 — Autenticação:** permitir a autenticação dos utilizadores.
- **RF2 — Desenho da aplicação:** definir o desenho e a organização da aplicação.
- **RF3 — Dimensão da grelha:** permitir escolher manualmente o tamanho da grelha, entre 10 e 20.
- **RF4 — Dificuldade:** permitir escolher o nível de dificuldade.
- **RF5 — Tema:** permitir gerar palavras cruzadas com um tema livre ou com um tema selecionado.
- **RF6 — Cliente/servidor:** a solução deve seguir uma arquitetura cliente/servidor.
- **RF7 — Guardar progresso:** permitir guardar o progresso e continuar mais tarde.

**Responsável principal:** Analista / Arquiteto de Sistemas.

### 2. Arquitetura do sistema

Documento que explica como a aplicação será organizada, quais são os seus componentes, como comunicam entre si e como será implementada a arquitetura cliente/servidor.

**Responsável principal:** Analista / Arquiteto de Sistemas, com a colaboração do Programador na definição da solução técnica.

### 3. Funcionamento da aplicação

Descrição dos passos que o utilizador deverá seguir para utilizar a aplicação, desde a autenticação até à criação, utilização e continuação de uma palavra cruzada.

**Responsável principal:** Analista / Arquiteto de Sistemas, com a colaboração do Programador para garantir que a descrição corresponde ao funcionamento previsto.

### 4. Decisões técnicas

Registo das decisões relativas à organização do sistema, às tecnologias escolhidas, à base de dados e à comunicação entre os diferentes componentes.

**Responsável principal:** Analista / Arquiteto de Sistemas, em conjunto com o Programador.

## Regras de organização

- Os documentos devem ser claros e fáceis de compreender.
- Cada funcionalidade deve ser descrita de forma objetiva.
- As alterações aos requisitos devem ser documentadas.
- As decisões técnicas devem ser registadas para que todos os membros compreendam a organização do sistema.
- Os responsáveis principais devem coordenar cada tema e pedir a colaboração dos restantes membros quando necessário.

## Resultado esperado

No final, esta pasta deve permitir compreender o que a aplicação tem de fazer, como será organizada e quais as condições que devem ser verificadas durante os testes.
